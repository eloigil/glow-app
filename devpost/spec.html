How GlowApp is built

One Next.js project with two halves. The screens run on her phone and keep the session in memory. Three small server routes run on your machine, hold the YouCam and OpenAI keys, and do all the talking.

Her skin tone is remembered in the browser, so the 20-unit tone call happens once. Saved looks keep their real images on the device, because YouCam links expire after 2 hours.

While building, everything runs in replay mode from recorded responses: 0 units spent, and judges can run it without keys.

Stack

Next.js + TypeScript Tailwind v4 Motion YouCam API OpenAI IndexedDB Hugeicons

Runs locally with npm run dev. No deploy yet; ready for Vercel later.

    Where data lives

    Memory

    Photo, analysis, looks, previews, step images.

    After a reload: gone, back to Welcome.

    localStorage

    Her skin tone, key glow.tone. Your choice.

    After a reload: reused, tone call skipped.

    IndexedDB

    Saved looks with real image blobs.

    After a reload: listed and replayable offline.

    fixtures/

    Recorded API answers, in the repo.

    For anyone: the app runs with no keys.

    One switch: API_MODE

    replay (default)

    Answers from fixtures/. 0 units. Used for almost all building.

    record

    Real calls, saved to fixtures/. Run once to capture the demo face.

    live

    Real calls, nothing saved. Only for step-by-step tutorial work when replay can't answer, and the demo recording.

    When it breaks

    Unusable photo

    YouCam's error code becomes a plain message: no face, more than one face, move closer, face the camera, too dark. Retry. Blur has no code, so it gets the generic message.

    Credits gone or YouCam down

    "We ran out of credits for the demo. Try later."

    LLM breaks the rules

    One automatic retry with the errors listed, then invalid steps are dropped. Never shows an unrenderable look.

    Slow tasks

    Latency isn't documented: poll every 2s, 60s timeout, skeletons and the scan sweep meanwhile.

    Decisions and what's left

    Your decisions

    Stack: accepted the Next.js + TypeScript + Tailwind v4 + Motion recommendation.

    LLM: OpenAI.

    Deploy: not yet, prepared for Vercel. No live URL is required.

    Products: skipped, YouCam has no catalog. PRD updated to match.

    Skin tone: Facial Color Tones, cached in localStorage.

    Replay mode: yes. Live calls only for the step-by-step tutorial, and only if needed.

    Build loop: yours to design.

    Details I derived (change any)

    Six SD concerns (acne, redness, dark circles, age spots, oiliness, eye bags) at 12 units. A concern is a "point" when its score is under 60. Renders come back as data URLs so they never expire. Saved looks use idb-keyval. One retry on bad LLM output.

    Verify early in the build

    Makeup VTO image limits (the docs disagree; test 1600px portrait). Real task latency. Whether mask URLs work in CSS mask-image cross-origin. That LLM pattern and color counts pass YouCam's rules.
